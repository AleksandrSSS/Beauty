## 0. Вимога (від користувача 2026-09-09, скрін `screens/beauty/14.png`)

Для нового майстра з графіком «тиждень через тиждень» (Weekly):

1. **Перший робочий день — будь-який день тижня** (не обов'язково понеділок).
2. **Робочі дні йдуть від першого робочого дня до кінця тижня, тобто до неділі** (перший тиждень —
   неповний: anchor..неділя — робочі).
3. **Далі — за звичайним графіком**: повні календарні тижні Пн–Нд через один
   (наступний тиждень — вихідний, потім робочий, і т.д.).
4. **Послідовність днів тижня не змінювати**: тиждень завжди починається з понеділка,
   сітка календаря Пн–Нд лишається як є.

Приклад (anchor = 17.09.2026, четвер):
- 17–20.09 — робочі (Чт–Нд, неповний перший тиждень);
- 21–27.09 — вихідні (повний тиждень);
- 28.09–04.10 — робочі;
- 05–11.10 — вихідні; і т.д.

## 1. Поточний стан (факти з коду — перевірено)

### 1.1. Формула Weekly зараз — 7/7 блоки від anchor (да дає «сім днів поспіль»)

`server/Data/RotationHelper.cs` (після відкату понеділкової нормалізації):

```csharp
RotationType.TwoTwo => (((day.DayNumber - master.RotationAnchor.DayNumber) % 4) + 4) % 4 < 2,
_ => (((day.DayNumber - master.RotationAnchor.DayNumber) % 14) + 14) % 14 < 7
```

Для anchor 17.09 (Чт) це дає робочі **17–23.09** (7 поспіль: Чт–Ср), 24–30.09 вихідні,
01–07.10 робочі, 08–14.10 вихідні, 15–21.10 робочі — що точно збігається зі скріншотом
(зелені 17,18,19,20,21,22,23 → далі 1,2,3,4,5,6,7 → далі 15). Тобто код працює
як написано, але написана семантика («7 днів поспіль від anchor») **не та, що вимагає
користувач** («від anchor до неділі, далі повні тижні»).

### 1.2. Що вже є і не ламає нову семантику

- Якір зберігається **як є** (без нормалізації) в `AddMaster`/`UpdateMaster` — так і треба лишити.
- Дефолт форми — `todaySalon()` (будь-який день) — коректно для нової семантики.
- Підпис поля «(перший робочий день)» — коректний, не чіпати.
- `PreviewRotation` будує вікно `anchor.AddDays(0..28)` і кличе `WorksOn` → після правки формули
  прев'ю стане коректним автоматично. Перший показаний день (anchor) лишиться першим робочим.
- `worksThisWeek`/`worksNextWeek` у `CatalogController` — «робочий день у найближчі 7 /
  наступні 7 днів» (діапазонні, без календарних меж) — валідні за будь-якої тижневої семантики,
  **не чіпати**.
- Коментар `RotationAnchor` в `Entities.cs` («перший робочий день (будь-який день тижня)»)
  — точний, не чіпати.
- `MasterDayOverride`/`EffectiveDay`, `MondayOf` — див. §1.3/§2.1.
- Сід (`DbInitializer`, Weekly з `CurrentMonday()`) — понеділок лишається валідним anchor,
  не чіпати.

### 1.3. Історія правок (щоб не ходити по колу)

1. Спочатку Weekly рахувався від `MondayOf(day) − anchor` із сирим anchor → «склеєні» тижні при
   не-понеділковому anchor (скрін 12.png).
2. Потім додали нормалізацію `MondayOf(anchor)` (календарні тижні Пн–Нд) — виявилась хибною
   для вимоги «7 днів поспіль» і була **відкочена** разом із методом `MondayOf` (його видалено).
3. Тепер вимога уточнена (§0): **календарні тижні, але перший тиждень — неповний (anchor..Нд)**.
   За іронією, це парність календарних тижнів від тижня якоря — близько до варіанта з п.2, але
   **без нормалізації anchor на запису** і з правилом «до anchor — не працює» (§2.1).

## 2. Зміни (детально)

### 2.1. `RotationHelper.WorksOn` — Weekly як парність календарного тижня (головна правка)

Файл: `server/Data/RotationHelper.cs`

```csharp
/// <summary>Понеділок тижня, до якого належить день.</summary>
public static DateOnly MondayOf(DateOnly day) => day.AddDays(-(((int)day.DayOfWeek + 6) % 7));

public static bool WorksOn(Master master, DateOnly day) => master.RotationType switch
{
    RotationType.TwoTwo => (((day.DayNumber - master.RotationAnchor.DayNumber) % 4) + 4) % 4 < 2,
    // Weekly: тиждень якоря (Пн–Нд) — робочий з дня anchor до неділі, далі повні тижні через один.
    // Дні раніше anchor — не робочі (майстер ще не почав). TwoTwo-гілку не чіпати.
    _ => day >= master.RotationAnchor
        && (((MondayOf(day).DayNumber - MondayOf(master.RotationAnchor).DayNumber) / 7) % 2 + 2) % 2 == 0
};
```

Пояснення:
- `MondayOf` **повернути** (був видалений при відкаті — відновити метод один в один).
- Парність рахується між понеділками → дельта завжди кратна 7, `/7` точний, «склеювання»
  тижнів неможливе за будь-якого anchor (проблема скріна 12.png закрита цим же).
- `day >= anchor → false` до старту: дні того ж календарного тижня **раніше** anchor
  (напр. Пн–Ср при anchor в Чт) — не робочі, бо «перший робочий день» ще не настав.
  Для всіх існуючих майстрів (anchor у минулому) це нічого не змінює.
- Коментар до `WorksOn` переписати під семантику §0.
- `TwoTwo`-гілку **не чіпати**.

Перевірка арифметики (anchor = Чт 17.09.2026, `MondayOf(anchor)` = Пн 14.09):
| День | MondayOf(day) | (Mon−14.09)/7 | Парність | Результат |
|---|---|---|---|---|
| 14–16.09 (Пн–Ср) | 14.09 | — (`day < anchor`) | — | вихідні (ще не почав) |
| 17–20.09 (Чт–Нд) | 14.09 | 0 | 0 | **робочі** |
| 21–27.09 | 21.09 | 1 | 1 | вихідні |
| 28.09–04.10 | 28.09 | 2 | 0 | **робочі** |
| 05–11.10 | 05.10 | 3 | 1 | вихідні |
| 31.08–06.09 (до anchor) | 31.08 | — (`day < anchor`) | — | вихідні |

## 5. Відкриті питання (узгодити перед реалізацією)

1. **Дні раніше anchor — вихідні?** (§2.1, гард `day >= anchor`). Пропозиція: **так**
   («перший робочий день» ще не настав). Альтернатива — чиста парність без гарда
   (тоді Пн–Ср тижня якоря світитимуться робочими ще до старту).
2. **Тижні раніше anchor** (минулі): за гардом — всі вихідні. Чи лишити так (на слоти не впливає —
   минуле відфільтровується, на графік у вікні today..+28 — лише якщо anchor у майбутньому)?
   Пропозиція: **так, лишити**.
