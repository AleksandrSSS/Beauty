# Beauty Salon — сайт салону (цирюльня + манікюр)

Тестовий проєкт: запис до майстра з підтвердженням кодом, особистий кабінет, адмін-панель.

## Стек
- **Backend**: ASP.NET Core 10 + EF Core + PostgreSQL (Docker)
- **Frontend**: React 18 + Vite + TypeScript
- Авторизація: JWT (клієнти — за кодом з повідомлення, адмін — логін/пароль)

## Швидкий старт

1. Запустити PostgreSQL:
   ```bash
   docker compose up -d
   ```

2. Backend (порт 5000, потрібен .NET 10 SDK або новіший):
   ```bash
   cd server
   dotnet run
   ```
   При першому запуску створюються таблиці та демо-дані (послуги, майстри, адмін).

3. Frontend (порт 5173):
   ```bash
   cd client
   npm install
   npm run dev
   ```

## Доступи
- **Адмін**: телефон `+380000000000`, пароль `admin123` (пароль і JWT-ключ — у **user-secrets**, не в appsettings):
  ```bash
  cd server
  dotnet user-secrets set "Jwt:Key" "<ключ>"
  dotnet user-secrets set "Admin:Password" "<пароль>"
  ```
- **Клієнти**: вхід за номером телефону + код підтвердження

## Конфігурація безпеки
- **CORS** — дозволені лише origins зі списку `Cors:AllowedOrigins` (appsettings.json; у prod задайте env `Cors__AllowedOrigins__0` тощо).
- **Таймзона салону** — `Salon:TimeZone` (за замовчуванням `Europe/Kyiv`). Слоти генеруються за "настінним" часом салону і зберігаються в БД в UTC.
- Подвійне бронювання захищене серіалізованою транзакцією в `POST /api/booking/create`.

## Можливості
- Послуги двох категорій: перукарня, манікюр
- Майстри працюють **тиждень через тиждень** (якірний понеділок; адмін може перемкнути тиждень)
- Бронювання: послуга → майстер → календар слотів на **14 днів** (поточний + наступний тиждень)
- Підтвердження запису кодом через: **SMS, Telegram, WhatsApp, Viber, Email**
- Нагадування **за 3 години** до візиту (фоновий сервіс, перевірка кожні 5 хв)
- Особистий кабінет: історія всіх записів, скасування, профіль
- Адмін-панель: CRUD послуг і майстрів, редагування часу/статусу бронювань

## Бекап
Бекап складається з **двох** частин і робиться разом:
1. `docker exec beauty-db pg_dump -U beauty -d beauty > backup.sql`
2. архів папки `server/wwwroot/uploads`

`pg_dump` **не** містить файлів фото — у БД лише шляхи. Втрата папки дає биті посилання; UI не ламається (працює fallback на ініціали), але фото зникають безповоротно.

## Канали нотифікацій (dev vs prod)
За замовчуванням усі канали працюють у **MOCK-режимі**: код і нагадування пишуться в консоль сервера та таблицю `notification_logs`, а у відповіді API повертається `devCode` (щоб можна було тестити без реальних SMS).

Для реальної доставки заповніть `appsettings.json` (або env-змінні):
- `Notifications:TelegramBotToken` — токен бота Telegram
- `Notifications:Twilio:*` — SMS і WhatsApp через Twilio
- `Notifications:Smtp:*` — Email
- Viber — підключається через шлюз (Infobip тощо) у `NotificationService.SendViberAsync`

## Графіки майстрів
- **Перукарі** (2 шт., чоловічі та жіночі стрижки) — посмінно **2/2**: 2 дні на зміні, 2 вихідні, чергуються між собою. Тип графіка `TwoTwo`, якір — перший робочий день.
- **Майстри манікюру** (2 шт.) — працюють **тиждень через тиждень**. Тип графіка `Weekly`, якір — понеділок робочого тижня.
- У майстра є поля `RotationType` (Weekly | TwoTwo) та `RotationAnchor` (якірна дата). Кнопка в адмінці: для Weekly зсуває якір на тиждень, для TwoTwo — на 2 дні (перемикає зміну).
